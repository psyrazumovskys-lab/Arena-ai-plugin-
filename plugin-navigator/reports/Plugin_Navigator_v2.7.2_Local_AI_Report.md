# Plugin Navigator 2.7.2 — загрузка моделей Ollama из приложения

**Дата:** 17 октября 2026
**Статус:** реализовано в исходниках, детерминированной сборке HTML и Windows-релизе; живая проверка загрузки — на целевой машине (Xeon E5-2666 v3, GTX 1060 3 ГБ).

## Мотивация

Пользователю приходилось скачивать модели Ollama вручную через терминал (`ollama pull …`). Теперь модель можно загрузить кнопкой прямо из раздела ИИ — с индикатором прогресса и автоматическим выбором после установки.

## Что сделано

В карточке Ollama (режим «Ollama на этом компьютере») появился блок **«Загрузка модели через Ollama»**:

- две кнопки рекомендованных моделей:
  - `qwen3.5:2b-q4_K_M` (≈1,9 ГБ) — компактный Q4-квант, помещается целиком в 3 ГБ VRAM (важно: дефолтный тег `qwen3.5:2b` — это Q8-сборка на 2,7 ГБ, для 3-гигабайтных карт она не помещается целиком);
  - `qwen3.5:4b` (≈3,4 ГБ) — точнее, часть слоёв уйдёт в RAM;
- поле для произвольного имени модели из библиотеки ollama.com/library;
- индикатор прогресса (проценты по данным Ollama) и кнопка «Остановить загрузку»;
- по окончании загрузки модель автоматически появляется в списке и выбирается; выбор сохраняется (`pn-ai-ollama-model`).

Технически: `POST /api/pull` со стримингом NDJSON (те же события `status`/`total`/`completed`, что показывал бы терминальный `ollama pull`). Веса сохраняет Ollama в своё хранилище — Plugin Navigator ничего не хранит и не удаляет.

Новые функции: `aiOllamaPull` (стрим загрузки + авто-выбор), `aiOllamaPullDOM` (обновление прогресса без перерисовки), `aiOllamaPullAbort` (остановка). Приоритет автоподбора модели (`aiOllamaPickModel`) дополнен компактным `qwen3.5:2b-q4_K_M` первым пунктом.

## Рекомендации по выбору модели (GTX 1060 3 ГБ)

| Команда | Загрузка | На этой карте |
|---|---|---|
| `ollama pull qwen3.5:2b-q4_K_M` | ≈1,9 ГБ | **рекомендуется**: веса целиком в VRAM, максимальная скорость |
| `ollama pull qwen3.5:4b` | ≈3,4 ГБ | заметно умнее, гибрид GPU+RAM (~10–20 ток/с) |
| `ollama pull qwen3.5:2b` (дефолт, Q8_0) | ≈2,7 ГБ | не помещается целиком — частичная выгрузка в RAM |

С 2.7.2 те же действия выполняются кнопками в самом приложении — терминал не нужен.

## Проверки

Пройдено в Arena:

- все замены патча применены единожды (assert в патч-скрипте);
- детерминированная сборка HTML (test_deterministic_build.py);
- полный прогон аудитов: test_user_guide, test_design_audit, test_chain_research_audit, test_plugin_guides, test_local_ai, test_deterministic_build — PASS;
- расширенный test_local_ai.py: маркеры `/api/pull`, `aiOllamaPull`, `data-ai-pull`, `qwen3.5:2b-q4_K_M` в исходнике и собранном HTML;
- полная Windows-сборка 2.7.2 (asar + postject + verify-windows: PASS, embedded HTML совпадает байт-в-байт).

Не пройдено в Arena (нет живого Ollama):

- реальная загрузка модели через `/api/pull` из приложения (прогресс, остановка, авто-выбор);
- живой ответ загруженной модели через `/api/chat`.

Чек-лист живой проверки: запустить Ollama → раздел ИИ → движок Ollama → «Проверить соединение» → кнопка `qwen3.5:2b-q4_K_M` в блоке загрузки → дождаться 100% → убедиться, что модель выбрана → задать тестовый вопрос → проверить «Остановить загрузку» на большой модели.
