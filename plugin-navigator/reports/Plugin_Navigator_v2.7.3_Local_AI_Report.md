# Plugin Navigator 2.7.3 — действия ИИ: цепочки, варианты, анализ настроек

**Дата:** 17 октября 2026
**Статус:** реализовано в исходниках, детерминированной сборке HTML и Windows-релизе; живая проверка генерации действий — на целевой машине.

## Мотивация

Пользователь просил расширить ИИ от «ответов на вопросы» до действий: составление цепочек, предложения вариантов, анализ настроек плагинов, рекомендации. Главный принцип программы — детерминированные правила авторитетнее модели — сохранён: **модель предлагает, человек подтверждает, движок проверяет**.

## Архитектура действий

Протокол `apply_chain` (без настоящего tool-calling, совместим с любой моделью):

1. System prompt (правила 8–10) описывает схему: ИИ завершает ответ fenced-блоком

```json
{"action":"apply_chain","mode":"replace|append","source":"Lead Vocal","steps":[{"name":"…","task":"…","lane":"insert|send|monitor|source","bus":"Send A","settings":"…","note":"зачем этот этап"}]}
```

2. `aiParseAction(text)` — извлекает последний валидный блок из ответа (оба движка: WebLLM и Ollama).
3. `aiActionHTML(m)` — карточка **«Предложение ИИ · требует подтверждения»** в чате: список этапов с бейджами задачи/маршрута, Starting Settings, пояснения, кнопки «Применить цепочку» / «Отклонить».
4. `aiApplyChain(m)` — валидация и применение:
   - имена плагинов сверяются с каталогом (`DB.plugins`); незнакомые — пропуск с уведомлением;
   - задача/маршрут/`source` — только из допустимых (`laneMeta`, `validSourceName`), остальное — `defaultLane`;
   - записи собираются через существующий `hydrateStepMeta` (обязательность, purpose, listenFor — от детерминированных правил);
   - подтверждение браузера при замене/добавлении к непустой цепочке;
   - `persistBuilder()` → переход в Конструктор, где Помощник порядка показывает свои замечания.

Ничего не применяется без нажатия кнопки. У предложения три состояния: pending → applied/dismissed.

## Контекст и лимиты

- `aiBuildContext` дополнен блоком **«ДОСТУПНЫЕ ЭТАПЫ ДЛЯ ИСТОЧНИКА»**: задачи выбранного источника + до 3 кандидатов из `candidatePlugins` — те же данные, что использует Конструктор. Если источник не выбран — передаётся список источников, и ИИ обязан уточнить его перед действием;
- лимит контекста 5800 → 6800 символов;
- генерация 600 → 800 токенов (цепочка с JSON длиннее обычного ответа);
- Ollama: `num_ctx: 8192` (дефолт Ollama обрезал бы расширенный контекст).

## Что теперь умеет ИИ (по запросу пользователя)

| Запрос | Поведение |
|---|---|
| «Составь цепочку для X» | уточняет источник (если не выбран) → предложение с предпросмотром |
| «Добавь de-esser / убери компрессор» | mode: append / replace + подтверждение |
| «Предложи варианты» | текстовое описание A/B/C + действие для рекомендуемого |
| «Разбери настройки» | поэтапный анализ Controls: назначение, что проверить на слух, риски; исправления — через действие |
| «Объясни цепочку / порядок» | как раньше — текстовый ответ |

Быстрая кнопка «Составь минимальную цепочку для …» добавлена в раздел ИИ.
