# Plugin Navigator 3.0.0 — инструментальный цикл: ИИ сам запрашивает данные каталога

**Дата:** 19 октября 2026
**Статус:** реализовано в исходниках, детерминированной сборке HTML и Windows-релизе; живая проверка — на целевой машине.

## Мотивация

Финальная ступень плана «максимальной свободы ИИ». Раньше контекст подбирала программа до отправки вопроса (retrieval), весь каталог в 8–16k токенов не влезает, и модель иногда честно отвечала «данных нет» там, где данные в программе есть.

## Что сделано

**1. Протокол «ЗАПРОС ДАННЫХ» (правило 18 системного промпта).** Если контекста не хватает, модель завершает текст структурированным блоком ЗАПРОС ДАННЫХ с JSON-инструментом, программа исполняет запрос, возвращает результат и просит продолжить ответ. Цикл повторяется до 3 раз.

**2. Шесть инструментов, все только читают:** search_plugins (поиск до 10 карточек через существующий retrieval), plugin_card (полная карточка, точное и регистронезависимое имя), family_plugins (все плагины семейства), category_plugins (до 120 имён с семействами), source_tasks (задачи и кандидаты источника), owned_plugins (коллекция «у меня есть»). Неизвестный инструмент и ошибки возвращаются моделью текстом — она может исправиться.

**3. Выбор протокола.** Рассматривался нативный tool calling Ollama, но выбран единый текстовый протокол для обоих движков (Ollama и WebLLM): модель уже надёжно владеет fenced-JSON блоками (тот же формат, что ДЕЙСТВИЯ), 2B-модели часто портят нативные tool_calls, а симметрия движков упрощает поддержку. WebLLM нативных инструментов не имеет.

**4. Интеграция в оба движка.** aiOllamaChat и aiWebLLMChat переписаны: диалог — массив сообщений (system/user/assistant/user…), стриминг сохранён, think-фикс Ollama (false → повтор с null) сохранён, лимиты aiNP учтены в каждом раунде. Видимый текст ответа очищается от служебных блоков запросов (aiStripToolRequests), поэтому пользователь видит только содержательный ответ.

**5. UX и персистентность.** Под ответом — строка «🔎 Данные запрошены у каталога: инструмент «запрос»» (aiToolCallsHTML); запросы сохраняются в истории диалога. Прерывание и остановка respected: при aiStopRequested цикл не продолжается.

## Проверки

Пройдено в Arena: замены по диапазону с пробами-ассертами; сборка HTML; `node --check`; 6 аудитов PASS; расширенные маркеры test_local_ai (ЗАПРОС ДАННЫХ, aiParseToolRequest, aiRunTool, aiStripToolRequests, все инструменты, ДАННЫЕ ИНСТРУМЕНТА, toolCalls, aiToolCallsHTML); Windows-сборка verify PASS.

Не пройдено в Arena: живой цикл с моделью (Ollama/WebLLM) — на целевой машине; качество решений 2B-модели о том, «что запросить», — предмет живой настройки.

## Совместимость

- оба движка, все настройки 2.9.0 сохранены; ДЕЙСТВИЯ и инструментальные запросы не конфликтуют (разные маркеры);
- рост промпта ~700 символов — в пределах num_ctx;
- версия 3.0.0 во всех конфигах, инструкции, README; отчёт содержит Ollama.
