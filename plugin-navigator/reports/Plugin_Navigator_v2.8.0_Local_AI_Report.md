# Plugin Navigator 2.8.0 — сканер установленных плагинов (VST)

**Дата:** 17 октября 2026
**Статус:** реализовано в исходниках, детерминированной сборке HTML и Windows-релизе; живая проверка на реальных папках VST — на целевой машине.

## Мотивация

Пользователь попросил: «навигатор сам добавлял новые плагины» — точнее: сам находил установленные на компьютере плагины и выдавал список нераспознанных агенту, который ведёт каталог. Рассматривались два варианта: встроенный сканер или отдельная программа. Выбран встроенный: сопоставление имён требует базы каталога (она живёт в Навигаторе), отметки «у меня есть» хранятся там же, а отдельная утилита означала бы второй канал обновлений и дублирование базы.

## Что сделано

В каталоге, рядом с «Импорт списка», появилась кнопка **«Сканер VST»**:

- **«Выбрать папку с плагинами…»** — системный диалог выбора папки; программа читает имена файлов VST2 (.dll), VST3 (.vst3, включая файлы внутри bundle-папок), CLAP (.clap) и AAX (.aaxplugin). Всё локально: ни один файл и ни одно имя не покидает компьютер;
- результаты накапливаются по нескольким папкам (VSTPlugins, VST3, CLAP и т.д.) и сохраняются локально (`pn-scan`);
- **«Отметить совпавшие "у меня есть"»** — сопоставление через механизм 2.7.6 (`ownedApplyNames`: нормализация + нечёткое вхождение), отметка одним подтверждением;
- нераспознанные плагины выводятся списком; **«Скопировать список для ИИ-агента»** формирует структурированный отчёт (версия каталога, дата, количество по форматам, нумерованный список нераспознанных с типом файла) — его нужно вставить в чат с агентом, который проверит плагины по официальным источникам и дополнит каталог проверенными карточками;
- **«Скачать .txt»** — тот же отчёт файлом; **«Очистить результаты скана»** — сброс.

Новые функции: `persistScan`, `scanExt`, `scanCleanName`, `scanFromInput`, `scanStats`, `scanAgentText`, `scanCopyFallback`, `scanPanel`, `scanResults`; состояние `state.scanOpen`/`state.scanFiles`; обработчики в `renderContent`.

## Архитектурное решение: выбор папки вместо нативного API

Автоскан стандартных путей через Neutralino Native API потребовал бы: включить `enableNativeAPI`, добавить `nativeAllowList`, втащить клиентскую библиотеку neutralino.js (в npm-реестре её нет — 404, распространяется через GitHub-релизы) и изменить модель безопасности приложения. Ни одно из этого нельзя проверить в песочнице — только на целевой машине. Выбор папки (input webkitdirectory) работает одинаково в браузере и в WebView2, не требует новых зависимостей и не меняет конфигурацию: один код, ноль рисков. Подсказка с типичными путями (C:\Program Files\VSTPlugins, Common Files\VST3, CLAP) закрывает главный минус ручного выбора.

## Предохранители

- сканер не изменяет базу каталога — только отметки коллекции пользователя;
- ИИ-контекст и промпты не менялись: движки WebLLM и Ollama работают как прежде; наполнение каталога остаётся prerogative агента с проверкой по официальным источникам;
- подтверждение перед отметкой и перед очисткой результатов;
- фильтрация мусорных подпапок (presets/banks/skins/manuals) и не-плагинных файлов.

## Проверки

Пройдено в Arena:

- все замены патча применены единожды (assert в патч-скрипте);
- детерминированная сборка HTML; полный прогон 6 аудитов — PASS;
- расширенный test_local_ai.py: маркеры `scanVstBtn`, `scanPanel`, `scanFromInput`, `scanCleanName`, `scanStats`, `scanAgentText`, `webkitdirectory`, «Скопировать список для ИИ-агента»;
- Node `--check` — синтаксис валиден; Windows-сборка verify PASS;
- юнит-проверка логики на Python-модели: очистка имён (суффиксы x64/64-bit, расширения), пропуск не-плагинных файлов, накопление результатов.

Не пройдено в Arena: живой скан реальных папок VST на Windows (диалог выбора папки в браузере и в WebView2) — на целевой машине.

## Совместимость

- метки «у меня есть» из 2.7.5/2.7.6 полностью сохраняются; экспорт/импорт резервных копий совместим (результаты скана в резервную копию не входят — это рабочие данные);
- работает в обоих движках ИИ (WebLLM и Ollama) без изменений промптов;
- версия 2.8.0 во всех конфигах, инструкции, README и Windows-метаданных EXE.
